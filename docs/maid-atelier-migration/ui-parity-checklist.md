# Maid Atelier UI / 功能对齐清单

从 [企划书](./企划书.md) §4.3 与 §8 抽出，供 P0–P4 勾选。缺任一 §4.3 硬约束，或任一「动漫高手锁定门」，即未达观感验收。

企划书 §8 已把下列锁定门列为验收门。对照图未纳入本仓库。未给出的 hex 不补。

## 色态（已定）

| 状态 | 色值 / 约束 |
| --- | --- |
| pending | `#5b8def` |
| blocked | `#d4546a` |
| busy | 暖琥珀。与 idle、online 分开。hex 未给出，不补 |

## 硬约束（§4.3）

未达任意一条即视为观感验收失败。

- [ ] **三栏**：左（会话 / 分区 / 工作流）· 中（对话 + Goal / progress）· 右（Markdown Reader）
- [ ] **色态**：pending `#5b8def`、blocked `#d4546a` 在进度/任务态上可辨
- [ ] **忙闲**：左栏或等价位置可见干员/会话忙闲
- [ ] **progress**：中栏有可追踪进度卡
- [ ] **@**：选择后有真实路由效果（非纯高亮）
- [ ] **气质**：深色、信息密度优先、圆形二次元头像、角色感克制
- [ ] **动漫高手锁定门**（下一节）全部满足

气质对照基准是本机 `/workspace/maid-atelier-target-ref.png`（企划草案点名；**不在本仓库**）。没有该图时，以现 OpenClaw 主线壳为对照，并由管理员主观判定「是同一工台」。

## 动漫高手锁定门

来源：动漫高手 UI 对齐补充。与 §4.3 同级，缺一条即未达观感验收。未提供 hex 的项只锁语义，不补色值。

### 色与状态点

- [ ] pending `#5b8def`、blocked `#d4546a` 可辨，且两者不混成紫
- [ ] busy、idle、online 三分：暖琥珀 / 冷薄荷 / sage，互不相等，也不并成一档绿
- [ ] 状态 pip 约 8px，深色描边（约 74% 黑混合），小点仍可读
- [ ] 未知忙闲不假绿、不伪造成空闲

### 壳与密度

- [ ] 三栏 Control 密度（信息密度优先，不是玩具化留白）
- [ ] 侧栏字号与行高比正文收紧半档
- [ ] @ 展开时，Goal / progress 仍可见
- [ ] 空态诚实文案：`No goal` / `No log` / `No checklist`
- [ ] 无 `Sample` 徽章抢焦点

### 头像

- [ ] 仅小圆二次元头像
- [ ] 换脸抽屉不遮住房间标题，也不遮住侧栏名字
- [ ] 禁止贴纸、换装剧场、大号角色扮演装饰

### 交互

- [ ] @ 气泡左条克制：宽 2px，比强调色略亮（「略亮」未给 hex）
- [ ] Reader 第一章颜色 = Goal 强调色（Goal 强调色 hex 未给出，不补）
- [ ] Draft 行（does not invite）用弱化色，不发出邀请
- [ ] Work 的真实步骤只读；手稿可打开
- [ ] 未知忙闲不得假绿

### 硬失败

出现任意一条即验收失败：

- [ ] 无玩具化 UI
- [ ] 无伪造的 progress 分数
- [ ] 无紫色 pip（pending 与 blocked 不得混紫）
- [ ] 无 `Sample` 叙述抢叙述位

## 界面对照（企划书 §8.1）

- [ ] 三栏比例与信息层级可对照本机参考图与现 OpenClaw 壳，管理员主观「是同一工台」
- [ ] 深色专业壳；无过度角色扮演装饰
- [ ] 圆形二次元头像位存在且可区分干员
- [ ] pending `#5b8def` / blocked `#d4546a` 在进度相关 UI 正确
- [ ] 忙闲状态在左栏（或约定等价位）可见；未知态不伪造成空闲
- [ ] 右栏 Reader 能打开至少一种 MD 来源并完成阅读

P0–P2 右栏只锁可读、可对照。轻量 MD 编辑是否单独立项，见企划书 §9.6，不作为本清单的当前必达项。工台不是 VS Code 克隆。

## 功能对照（企划书 §8.2）

- [ ] 创建并打开会话；消息进出经 gateway 真实可用（P1）
- [ ] @ 选择后消息进入目标干员/会话，有日志或会话证据（P2；对齐 OpenClaw #10 意图）
- [ ] Work / 勾选产生 progress 卡，状态可切换且色态正确（P2）
- [ ] 多 profile 至少 2 干员可切换监督；P3 前可降级为「可切换」（P3）
- [ ] 群房最小监督：能看、能指派、能回读（P3）
- [ ] Pull in 等标明起草的能力若露出 UI，须标 draft，不得默认生产路径（#10 仍为 draft）
- [ ] 安全：默认监听与认证符合 Hermes 基线；无明文密钥进插件前端包

## 弃用门槛（企划书 §8.3，P4）
