## 1. 背景与目标

### 1.1 背景

当前多智能体工台 **Maid Atelier** 压在 OpenClaw Control UI 上：三栏壳、深色专业观感、圆形二次元头像、忙闲与 progress、@ 路由与群房监督等已陆续合入主线。同期评估了 DeepSeek coding harness（DSH）与 Hermes：DSH 更像编码 harness，整盘魔改成工台不划算；Hermes 产品位更接近（profile、网关、仪表盘/桌面插件、记忆、cron、聊天通道），但仍不等于「换皮」。

管理员决策：**先 fork Hermes，写企划把现有能力迁过去，最终界面观感与现 Maid Atelier 大致一致**。本文件即该决策的工程与产品约束说明书。Fork 地址已定为 [`https://github.com/L1nkkkk/hermes-agent`](https://github.com/L1nkkkk/hermes-agent)。

### 1.2 产品终态（管理员口径）

工台要覆盖：**浏览 + 搜索 + 阅读 + 笔记 + 编码**。它是工作台，**不是 VS Code 克隆**。右栏以 Markdown Reader 为主，**后续可演进为 MD 编辑**，但 P0–P2 不以完整 IDE 为目标。

### 1.3 本企划目标

1. 在 Hermes fork 上复现 Maid Atelier 的 **三栏交互语义与视觉约束**（非像素级复刻）。  
2. 把已合能力（会话分区、忙闲、progress、@ 真路由、Work 落卡、群房监督等）映射到 Hermes 的 profile / gateway / dashboard·desktop plugin 模型。  
3. 给出分阶段路线、风险与验收清单，供管理员拍板「迁 / 缓迁 / 双栈并行多久」。

### 1.4 成功判据（一句话）

管理员打开 fork 后的 Hermes 壳，能在 **同一套三栏逻辑** 下完成日常监督与指派；观感对得上本机参考图 `/workspace/maid-atelier-target-ref.png`（若存在）与现 OpenClaw 主线体验，而不是「换了个聊天仪表盘」。该图不在本仓库内。

## 3. 为何选 Hermes fork（相对继续 OpenClaw / DSH）

### 3.1 相对继续只压 OpenClaw

| 维度 | 继续 OpenClaw | Hermes fork |
| --- | --- | --- |
| UI 沉没成本 | 已付清大部分 | 需重接壳与插件 |
| 多 agent 隔离 | 依 OpenClaw 会话/角色模型 | **Profile** 天然隔离 config / 记忆 / session / skills / gateway |
| 扩展面 | Control UI 定制路径已熟悉 | **Web Dashboard 插件** + **Desktop Plugin SDK**（`@hermes/plugin-sdk`）可叠自定义三栏 |
| 产品故事 | 「我们魔改的 OpenClaw」 | 「基于 Hermes 的 Maid Atelier 工台」——更贴近个人智能体平台叙事 |
| 风险 | 上游演进与 fork 漂移 | 上游策略/记忆/升级通道不同，要重验信任边界 |

**选 Hermes 的理由（管理员已倾向）**：底座更接近「多 profile 工台」；仪表盘与桌面均可插件化，长期比在 coding harness 上硬拧合适。代价是 **重造壳与接线**，故必须分期，且 UI 约束写死。

### 3.2 相对 DSH

DSH 是 coding harness：插件化可叠功能，但多干员/计费/群房监督不是其主场。结论已定：**不整盘魔改 DSH**；仅可借鉴插件边界思路，不作为本迁移宿主。

### 3.3 本 fork 的定位声明

- **不是** 上游 Hermes 的主题换肤。  
- **是** 以 Hermes 运行时与 profile/gateway 为宿主，**复刻 Maid Atelier 工台产品面**。  
- 上游能力（记忆、cron、通道、多网关桌面连接等）按需接入；与工台冲突时，**工台交互语义优先**，并在决策点显式记录偏差。

## 4. 迁移范围与非目标

### 4.1 范围内（In Scope）

1. **壳对齐**：三栏结构、深色专业风、圆形头像、忙闲指示、状态色（含 pending / blocked）。  
2. **会话模型映射**：OpenClaw 会话/分区 → Hermes profile + session（见 §5）。  
3. **中栏语义**：对话流 + 目标 progress 卡（含 Work 落卡语义）。  
4. **@ 路由语义**：提及 → 真实路由到目标 profile/session（对齐 #10 意图）。  
5. **右栏 Reader**：Markdown 只读对照；为后续编辑留接口，不在本期做完整编辑器。  
6. **群房监督最小集**：多干员可见、可指派、可回读。  
7. **双栈并行期运维约定**：OpenClaw 仍为生产壳，直到验收清单勾完。

### 4.2 非目标（Out of Scope）

- 像素级 1:1 复刻每一帧动画/灯效。  
- 把 Hermes 做成 VS Code / 完整 IDE。  
- 一键迁移全部历史会话字节级兼容（允许导出/只读归档）。  
- 重做 DSH、或并行维护第三套 UI 宿主。  
- 在本规划文档里把未对照过的 SHA 写成规格、附截图或伪造 PR 链接。运行时代码在 Desktop 插件里，不在本文件里。

### 4.3 「界面大致一致」的硬约束

以下任一缺失，即视为 **未达观感验收**。勾选表见 [ui-parity-checklist.md](./ui-parity-checklist.md)。

1. **三栏**：左（会话/分区/工作流）· 中（对话+进度）· 右（MD Reader）。  
2. **色态**：pending `#5b8def`、blocked `#d4546a` 在进度/任务态上可辨。  
3. **忙闲**：左栏或等价位置可见干员/会话忙闲。  
4. **progress / @**：中栏有可追踪进度卡；@ 选择后有真实路由效果（非纯高亮）。  
5. **气质**：深色、信息密度优先、头像圆形二次元、角色感克制——对照本机 `/workspace/maid-atelier-target-ref.png`（该文件不在本仓库）。

## 5. 架构映射表（OpenClaw 概念 → Hermes）

> 下表按本 fork 上的 Desktop 插件改过。没有干净接口的行写残留，不写成已接通。

| OpenClaw / Maid Atelier | Hermes 对应 | 迁移策略 | 备注 |
| --- | --- | --- | --- |
| Control UI 整壳 | **Desktop 插件** `maid-atelier` | `@hermes/plugin-sdk` 注册 `/atelier` 路由、侧栏、命令面板。三栏在页面网格里 | 不注册三块 pane-tree 磁贴，也不用 Dashboard Chat |
| 会话 Session | Profile 下的 sessions | `session.list` / `session.resume`。一会话一条 Hermes session | 跨 profile 不共享记录 |
| 干员 / 角色 | **Profile** | 侧栏一名一 profile，头像绑 profile id | 一进程多 profile；列表走当前连接上的 `profiles.list` |
| Gateway | Hermes gateway | `host.request` / `host.requestProfile` | 网关没开时状态是未知，不涂在线绿 |
| 中栏对话 | 插件自己的记录条 | `prompt.submit` + 每 4 秒 `session.resume` | 不是 Desktop Chat 流，也不是 `message.delta` |
| Work → progress 卡 | 插件存储 `progress:{sessionId}` | 写入再读回。失败不更新 UI | **没有** `progressCard.put`。别的界面看不到 |
| @ 真路由 | `host.requestProfile` + `prompt.submit` | 先建对方会话，失败再走对方主会话。房间会话不收这一轮 | 回复不进房间记录。这是平台缺口，不是少写一行 |
| 群房监督 | 工台成员勾选 + 上面的投递 | 能看、能指派。回读要打开对方会话 | 成员记录不是 session-child 图 |
| Markdown Reader | 插件右栏 | 把恢复出的记录渲染成 Markdown | SDK 没有安全读文件口。不刮 `/api/files/read` |
| 记忆 / cron / 通道 | Hermes 原生长处 | 未接进工台 | P3+ ，不阻塞壳 |
| 技能 / MCP | Profile 级 skills、MCP | 未接进工台 | Dashboard 仍适合配置面 |

### 5.1 宿主

- **主路径（已按这个做）**：Hermes Desktop + 捆绑插件 `maid-atelier`。  
- **辅路径**：Web Dashboard 仍只适合 profile / 密钥 / skills，不承担工台。  
- **不做**：用 Dashboard Chat 冒充 Maid Atelier。

## 6. 分阶段路线图

### P0 — 壳对齐（先像）

- Fork 已在 [`https://github.com/L1nkkkk/hermes-agent`](https://github.com/L1nkkkk/hermes-agent)。上游 Hermes tag/commit 仍空。

- **出口**：三栏可辨。气质的管理员主观验收还没做。

### P1 — 数据与会话

- Profile 列表进左栏；打开会话进中栏；忙闲接 `session.active_list`，读失败显式未知。  
- Reader 读的是恢复出的会话记录，不是工作区文件。  
- **出口**：假网关组件测试通过。活网关日常对话未验。

### P2 — 路由与 progress

- #10 语义已移植到插件能碰到的接口：@ → 目标 profile 的 `prompt.submit`；Work 勾选 → 插件存储读回；pending / blocked 上色；Draft line 不邀请。  
- **出口**：单机假网关上的「指派—跟踪」闭环有测试。进度卡不出插件。@ 回复不回房间。

### P3 — 通道与多干员

- 多 profile 可切换。群房能看、能用 @ 指派。回读不是房间聚合记录。  
- 聊天通道 / cron / 多网关监督没接。  
- **出口未到**：多干员监督还不能丢掉 OpenClaw。

### P4 — 收尾与弃用 OpenClaw UI

- 验收清单全绿；历史会话归档策略执行。  
- OpenClaw Control UI 标为只读/冻结；文档与入口切到 Hermes fork。  
- 清理双栈脚本与临时桥。  
- **出口**：生产入口唯一；OpenClaw UI 不再作为日常壳。

### 并行约定

P0–P2 期间 **OpenClaw 仍为生产壳**；Hermes 侧仅预发/管理员试用。任何「切默认入口」必须走 §9 决策点。

## 7. 风险与成本

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| **@ / 群房与 profile 隔离冲突** | P2–P3 延期 | 先做「显式投递 API」而非共享记忆；共享需求走外部记忆或监督元会话 |
| **Desktop vs Dashboard 双 SDK** | 重复劳动 | 工台只押 Desktop；Dashboard 限配置 |
| **信任边界 / 安全策略差异** | 误开放网关或插件权限 | 对照 Hermes 官方：公网 bind 需认证；插件热加载目录权限收紧；fork 默认安全基线文档化 |
| **记忆自动写入** | 两进程同 profile 污染 | 严格一 agent 一 profile；文档写入运行手册 |
| **双栈并行期成本** | token、人力、心智负担 | 设并行上限（建议 ≤2 个大版本周期）；P2 出口评审是否继续 |
| **上游升级打破插件 API** | 壳回归 | fork 钉版本；插件 API 适配层；关注官方 plugin-sdk changelog |
| **会话历史不全迁** | 抱怨「丢上下文」 | 只读归档 + 关键会话提示；不承诺字节级兼容 |
| **Token / 模型费用** | 迁测双跑烧钱 | 预发限模型；回归用固定脚本会话 |

**成本粗估（量级，非报价）**：P0–P1 以 UI/接线为主；P2 路由层最贵；P3 群房可能超过 P0+P1 之和。若 P2 实测「无干净路由点」，应触发 §9「缓迁/停迁」而非硬刚。
